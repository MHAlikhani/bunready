## Decisions locked

| # | Decision | Why |
| --- | --- | --- |
| D1 | Exit codes `0` ok / `1` blockers / `2` usage-or-incomplete | CI gate is `exit != 0` only, so `risk` can never wedge a pipeline. See ADR 0002. |
| D2 | Severity = `blocker` \| `risk` \| `info` | One question decides: does this break with no user action? |
| D3 | `Result<T>` everywhere; nothing throws across module boundaries | Callers must render or recover; typed errors carry a `hint`. |
| D4 | Zero third-party runtime dependencies | Scan-time code runs on user machines; dev deps only. |
| D5 | `run(argv, io)` is the whole CLI; `index.ts` is 2 lines | Every behaviour is reachable from tests; the process boundary stays thin. |
| D6 | Colour never carries meaning alone | `NO_COLOR`, monochrome terminals and CI logs keep full information. |
| D7 | Hooks via `simple-git-hooks`, not git-hooks frameworks with downloads | Pure JS, no binary fetch on install. |
| D8 | Branch protection deferred to the CI phase | Required status checks need CI to exist first. |
| D9 | Compat data is vendored + versioned JSON with `source` links | ADR 0001; `bunready` must work offline and never phone home. |
| D10 | `assist.actions.source.organizeImports` on in Biome | Import order is not a review topic. |

## Open questions

- **O1** npm publish scope: the `bin` entry ships TypeScript and requires the
  `bun` runtime on the user's machine. Acceptable for a Bun tool; needs a
  decision before phase 6 (ship `.ts` or compiled `.js`).
- **O2** Windows hook execution: hooks are installed; `commit-msg` uses
  `$1`-style args and must be sanity-checked on a real failing commit.
- **O3** `--run` executes target code in a temp copy. Temp-dir strategy,
  `--no-network`, and cleanup-on-failure are undecided (phase 4).
- **O4** Coverage excludes only tests; `index.ts` is unloaded by tests and
  therefore not counted. Revisit if the threshold ever gets close.
